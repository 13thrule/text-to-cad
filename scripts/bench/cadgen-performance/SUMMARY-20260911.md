# Performance work: results and remaining gaps

Cadgen now reuses more work when loading, rebuilding and displaying STEP files,
and handles browser resource ownership and failed replacements more carefully.
It can publish a complete editing preview before STEP saving finishes.
The cache still uses immutable objects and atomic input indexes; model authors
use ordinary CAD code and decorators, with no cache or session utilities.

This is a progress checkpoint, not a claim of complete FreeCAD parity. Further
work is investigating unused work in cold document compilation. All active
experiments use a nine-part planetary assembly, a 24-instance fixture or small
curved parts. The large hand is excluded from further testing.

## What changed

- **Imported geometry is reusable.** Unchanged STEP imports reconstruct cached
  canonical geometry without parsing STEP text again, including across processes.
  Cache deletion and corrupt derived objects recover from the saved document.
- **Editing and saving are separate.** Complete immutable source results can
  reach the viewer and parent models before STEP persistence finishes. Explicit
  builds still wait for every declared child output and validated saved bytes.
- **Backend caches have clear ownership.** They retain canonical bytes and
  bounded scalar results. Each consumer gets private native geometry. Operation
  keys include the actual installed kernel identity; disk hits obey the RAM cap.
- **Rendering does less repeated work.** Initial loads defer selectors, repeated
  parts share compatible GPU geometry, obsolete workers can be stopped, and
  detail updates reuse unaffected resources. Bounded groups reduce scene updates.
- **Failures preserve a usable view.** Replacements retain their allocations
  until actual adoption or disposal. Partial failures restore exact old meshes
  and matching selectors; stale replies cannot replace a newer model.
- **A retention defect is fixed.** Repeated detail updates no longer retain
  hundreds of obsolete selection/workspace contexts.

Imported new-value previews arrived in 153–195 ms, before complete saving.
Procedural new-value previews remained around 500 ms: the 250 ms target is
still unmet there. The empty-store import regression includes process startup
and canonical publication absent from the original parser-only path. An
already-warm daemon measured 1,354 ms for that first import, excluding its startup.
Cold browser memory did not improve uniformly.

## Latest incremental improvements

The bounded all-link implementation was compared against the same current
operation-cache scheme. All 96 builds produced matching source/document trees,
actual STEP outputs and exact child pins across conditions.

| Split-model edit | Preview before | Preview after | Complete save before → after |
|---|---:|---:|---:|
| Previously saved geometry | 221 ms | 206 ms | 421 → 422 ms |
| Previously saved placement | 191 ms | 164 ms | 399 → 375 ms |
| New geometry | 235 ms | 215 ms | 655 → 649 ms |
| New placement | 186 ms | 161 ms | 613 → 598 ms |

These are backend publication events, not browser frames. The study is small,
interleaved and imperfectly balanced by run position. Save timings remain mixed;
new-output readback still takes about 250–257 ms. See the
[bounds study](DEFERRED-ASSEMBLY-FEASIBILITY-20260911.md).

Viewer batching reduced six publications to two during each zoom phase. Against
the same implementation configured for one replacement at a time, four-at-a-time
grouping completed refinement about 42 ms sooner, while the first refined draw
arrived 7–11 ms later. Separately, the same 246 detail adoptions retained 9
workspace contexts instead of 503; collected backing storage fell from 19.953
to 3.393 MB. These concern separate experiments, not one combined memory/speed
claim. See [batching](VIEWER-LOD-BATCH-MODERATE-20260910.md) and
[selection retention](VIEWER-SELECTION-RETENTION-20260911.md).

## Comparison with FreeCAD

FreeCAD keeps an editable document and updates the affected objects. On the
same STEP and machine, its headless geometry edit/recompute measured 6.43 ms;
a retained placement change measured 0.042 ms. Meshing the changed part
separately took about 4.15 ms. Exporting the whole assembly to STEP still took
about 222 ms, and reading that export back took another 208 ms.

Cadgen has adopted several corresponding mechanisms: retained browser geometry,
component reuse, finer decorated-child dependencies and preview publication
before persistence. Its remaining gap comes from rerunning arbitrary Python
model bodies, validating private native ownership, publishing reusable canonical
objects and moving display data into a browser. Headless OCCT itself does not
impose this gap—the FreeCAD measurements were also headless.

We did not measure FreeCAD GUI frame latency or establish equal display-mesh
quality. Native meshing was tested on bounded fixtures; its complete extraction
cost was worse on curved parts, so the production JS mesher remains. See the
[FreeCAD measurements](WARM-COMPARISON-20260910.md#freecad-on-the-same-step) and
[native meshing decision](RWGLTF-MODERATE-QUALITY-20260910.md).

## Validation and viewer

The current viewer passes 1,015 shared JavaScript tests, 506 client tests and
the moderate interaction/failure checks. The bounded backend change adds 22
focused tests, and all 1,619 integrated package tests pass. Details are in the
[validation report](VALIDATION-20260910.md).

The isolated installed wheel matches all 217 package files to source. Ordinary
decorated child builds, source-free STEP/mesh exports, posed images and animation
pass, as do actual serving-process provenance and all 22 HTTP viewer assets.

[the planetary assembly on port 3276](http://127.0.0.1:3276/?file=planetary.step).
