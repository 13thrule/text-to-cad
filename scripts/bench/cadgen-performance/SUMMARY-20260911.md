# Performance work: results and remaining gaps

Cadgen now reuses more work when loading, rebuilding and displaying STEP files,
and handles browser resource ownership and failed replacements more carefully.
It can publish a complete editing preview before STEP saving finishes.
The cache still uses immutable objects and atomic input indexes; model authors
use ordinary CAD code and decorators, with no cache or session utilities.

The subsequent [Moonwatch study](MOONWATCH-20260911.md) exercises a 117 MB saved
watch and real source edits. It found and corrected additional whole-tree
validation and worker-reuse costs: complete cold coarse-display preparation fell
from 62 seconds at the preceding checkpoint to 34 seconds. Visual review then
found that the refinement rule can leave the watch below standard detail;
full standard-quality browser completion remains unmeasured. Correcting rejected warm
mesh-cache hits cut headless snapshots from 22.64 to 2.16 seconds, with unchanged
pixels. Removing duplicate kinematics resolution reduced a matched parent
rebuild from 36.54 to 32.15 seconds. The original attempted viewer load had
remained incomplete after several minutes. That study records the larger
model's remaining edit/save costs separately from the moderate assembly results
below.

The latest follow-on adds optional pure feature factories, exact-reference
assembly composition, selective browser updates, bounded preview notifications
and the no-VTK dependency route. Ordinary bare model scripts also avoid loading
unused geometry back into their initiating process after saving. Its native benchmarks cover 3, 9 and 24 parts,
including a real nine-part planetary assembly. The large hand was excluded.
These are substantial incremental gains, not full FreeCAD parity or a measured
100× application speedup. The latest integration evidence is in the
[follow-on report](FOLLOWON-INTEGRATION-20260911.md).

## Latest follow-on results

The largest full-command improvement came from removing that discarded return.
Actual `python model.py --json` process lifetimes fell as follows, with warm
workers and identical saved STEP bytes:

| Model / command | Before | After | Speedup |
|---|---:|---:|---:|
| 2 occurrences, unchanged | 2.63 s | 113 ms | 23.2× |
| 24 occurrences, unchanged | 2.75 s | 113 ms | 24.3× |
| 2 occurrences, new placement | 2.71 s | 188 ms | 14.4× |
| 24 occurrences, new placement | 2.93 s | 231 ms | 12.7× |

These are one pair per case, with alternating order and separate stores. They
include process startup and exit; new placement revisions are unprimed. Calls
that use their returned geometry still receive it. The conservative shortcut
requires an uninstrumented real-file CPython main module. See the
[command-completion study](R5-SCRIPT-COMPLETION-20260911.md).

An expensive helper can now use `@memo` to skip its unchanged Python and
builder work. Changing one plate in a nine-part assembly produced exactly
**eight reused features and one recomputation**. Both benchmark modes produced
identical STEP bytes; the other eight components and placements stayed intact.
Existing decorated-child assemblies also avoid repeated native containers and
serialization through eligible `Compound(children=parts)` calls automatically.

| Task | Before this mechanism | With it | Speedup |
|---|---:|---:|---:|
| 3 drilled plates, placement preview | 171.6 ms | 49.0 ms | 3.50× |
| 9 drilled plates, placement preview | 583.8 ms | 123.6 ms | 4.72× |
| 24 drilled plates, placement preview | 1,603.1 ms | 235.3 ms | 6.81× |
| 24 drilled plates, complete STEP save | 1,704.0 ms | 309.0 ms | 5.51× |
| Change one of 9 plates, preview | 578.3 ms | 140.1 ms | 4.13× |
| Change one of 9 plates, complete STEP save | 675.2 ms | 190.6 ms | 3.54× |
| Planetary assembly, reference-composed placement preview | 142.8 ms | 92.4 ms | 1.55× |
| Planetary assembly, reference-composed complete save | 374.1 ms | 322.2 ms | 1.16× |

These are matched enabled/disabled increments on the current source, with warm
kernels, three alternating pairs per case, and ordinary operation caching in
both feature modes. They exclude source writing and startup. Preview means
backend publication, not a browser frame. The feature cases repeat at most six
prototype shapes; the planetary case has nine parts and 582 faces. The new
feature output revisions were not equally readback-prewarmed, so save timings
include a first-in-pair readback limitation. The reference comparison did
prewarm both members' exact readback. Do not multiply these independent gains.
See [feature factories](FEATURE-FACTORIES-20260911.md) and
[reference composition](REFERENCE-ASSEMBLIES-20260911.md).

The biggest helper-only gain was a 12-hole builder at **75.0 → 4.8 ms (15.7×)**.
Cheap helpers can become slower, so `@memo` belongs on expensive pure
computations. It requires value-based deterministic geometry under an unmodified
CAD runtime; unsupported contexts/code execute normally. It does not discover
an incremental feature graph inside arbitrary monolithic Python.

The dependency audit removed cadgen's redundant full-OCP/VTK requirement from
fresh installs. The matched provider download closure is **184.09 → 59.41 MiB**,
a 68% reduction. The clean required Python dependency closure occupies
623.83 MiB. Existing environments keep already-installed packages; no startup
or RAM gain is inferred from disk size. See the
[dependency audit](DEPENDENCY-AUDIT-20260911.md).

Final browser interaction checks pass: the 24-occurrence scene stays visible
through edits and a failed replacement, exact face/edge picking recovers on a
new revision, and equivalent hydrated states return to the same GPU resource
counts. The final production viewer also renders the nine-part planetary
assembly correctly. Replacing idle preview polling with held notifications
improves these source-write-to-first-main-scene-draw observations:

| Browser edit | Previous polling | Held notifications |
|---|---:|---:|
| 2 occurrences, placement | 409 ms | 186 ms |
| 2 occurrences, one-part geometry | 349 ms | 290 ms |
| 24 occurrences, placement | 351 ms | 245 ms |
| 24 occurrences, one-part geometry | 369 ms | 338 ms |

These are individual pairs at recorded polling phases on the final runtime,
ending when the CPU renderer call completes, not when the compositor presents
the frame. The 24-part first-edit pair includes a display-payload transition.
A separate exact authored-baseline check preserves all 24 GPU geometries at
the same detail level; changing tessellation level correctly replaces them.
See [preview delivery](PREVIEW-DELIVERY-20260911.md) for raw evidence, the bounded
baseline correction and limitations. Historical whole-branch studies below
remain separate checkpoint comparisons.

## What changed

- **Imported geometry is reusable.** Unchanged STEP imports reconstruct cached
  canonical geometry without parsing STEP text again, including across processes.
  Cache deletion and corrupt derived objects recover from the saved document.
- **Display preparation is separate.** Native geometry loads and publishes
  without extracting every display surface. Cached meshes can render after
  SURF objects have been deleted; selecting a face later recovers the exact
  surface those triangles used. Mesh admission checks size and identity before
  downloading, then validates bytes and rendering metadata before adoption.
- **Editing and saving are separate.** Complete immutable source results can
  reach the viewer and parent models before STEP persistence finishes. Explicit
  builds still wait for every declared child output and validated saved bytes.
- **Backend caches have clear ownership.** They retain canonical bytes and
  bounded scalar results. Each consumer gets private native geometry. Operation
  keys include the actual installed kernel identity; disk hits obey the RAM cap.
  Manual cleanup now retains saved-document trees even after source records are
  forgotten, avoiding unnecessary reparsing on the next artifact read.
- **Rendering does less repeated work.** Initial loads defer selectors, repeated
  parts share compatible GPU geometry, obsolete workers can be stopped, and
  detail updates reuse unaffected resources. Bounded groups reduce scene updates.
- **Recoverable failures preserve a usable view.** Replacements retain their allocations
  until actual adoption or disposal. Partial failures restore exact old meshes
  and matching selectors; stale replies cannot replace a newer model. If
  restoration fails, the viewer attempts full teardown and reports the error.
  Failed cleanup stops detail work and retains ownership charges until cleanup
  is confirmed.
- **A retention defect is fixed.** Repeated detail updates no longer retain
  hundreds of obsolete selection/workspace contexts.
- **Canvas selection works with lazy topology.** Clicking a collapsed assembly
  selects its component immediately. Expanding it loads selectable topology;
  subsequent canvas clicks select exact face and edge references. Older pending
  clicks cannot override a newer selection or a replaced model.

## Earlier geometry/display improvements

The [final public native study](PUBLIC-NATIVE-HARD-CUT-20260911.md) compares the
runtime immediately before geometry/display separation with the integrated
runtime. Kernels are already warm, disk stores are empty where stated, and
the pool uses one worker. Four observations per condition were interleaved on
a shared host; unrelated application activity remains a limitation.

| Public task | Before separation | After separation |
|---|---:|---:|
| First native read, empty disk store | 1,180 ms | 407 ms |
| Repeated native read | 28.9 ms | 23.8 ms |
| Placement edit, STEP write and saved readback | 1,441 ms | 615 ms |
| Empty-store CLI compile, including CLI startup | 1,278 ms | 487 ms |
| Unchanged CLI compile, including CLI startup | 139 ms | 195 ms |
| First native read plus every display surface ready | 1,201 ms | 1,318 ms |

Native paths improve substantially; complete surface preparation is 5–10%
slower in this window, and the unchanged CLI path regresses. Neither surface
readiness nor native publication is a browser-frame measurement. These results
supersede the prototype for public-path claims and do not replace the earlier
cross-version procedural comparison.

The CLI regression was traced to three full geometry validations per cache
hit. Commit `05826cfc1` reduces this to one verified snapshot, rechecks the
actual file digest before returning it, and preserves generated-model and
export checks. All 89 focused tests pass. That corrects the duplicated work;
the table above records the earlier measured checkpoint, since no further
planetary timing run was performed.

The bounded all-link implementation was compared against the same current
operation-cache scheme. All 96 builds produced matching source/document trees,
actual STEP outputs and exact child pins across conditions.

| Split-model edit | Preview before | Preview after | Complete save before → after |
|---|---:|---:|---:|
| Previously saved geometry | 221 ms | 206 ms | 421 → 422 ms |
| Previously saved placement | 191 ms | 164 ms | 399 → 375 ms |
| New geometry | 235 ms | 215 ms | 655 → 649 ms |
| New placement | 186 ms | 161 ms | 613 → 598 ms |

These are backend publication events, not browser frames. The study is small,
interleaved and imperfectly balanced by run position. Save timings remain mixed;
new-output readback still takes about 250–257 ms. See the
[bounds study](DEFERRED-ASSEMBLY-FEASIBILITY-20260911.md).

The [raw compilation cleanup](COLD-COMPILE-CLEANUP-20260911.md) removes unrelated
source discovery and unused native/adaptive preparation. The nine-part median
improves only from 1,095 to 1,079 ms in resident interpreters. All 36 calls preserve
exact canonical outputs. First-time SURF extraction still takes about 758 ms,
which motivated geometry/display separation.

The [resident geometry-core study](DEFERRED-SURF-CORE-20260911.md) measured
native cold read/publication at **1,126 → 342 ms**, warm native reconstruction at
**28.0 → 17.5 ms**, and a placement edit/save/readback at **1,295 → 522 ms**.
Those are isolated core timings, excluding public dispatch and browser work.
All surfaces ready still took about 3% longer overall. The public-path study
above is the production measurement; extraction has moved off the native path
but still has to happen for a complete new display.

The [final three-part procedural check](TINY-PROCEDURAL-AND-CANVAS-20260911.md)
completed 16 calls in 28.9 seconds. All conditions preserved actual STEP bytes,
geometry, appearance, placements and exact child pins. Its single observations
per category and a baseline child-worker startup cost make it unsuitable for
claiming a stable speedup or resolving the nine-part preview target. An earlier
incomplete 12-call attempt is retained separately and is not part of the matched
four-condition result.

Viewer batching reduced six publications to two during each zoom phase. Against
the same implementation configured for one replacement at a time, four-at-a-time
grouping completed refinement about 42 ms sooner, while the first refined draw
arrived 7–11 ms later. Separately, the same 246 detail adoptions retained 9
workspace contexts instead of 503; collected backing storage fell from 19.953
to 3.393 MB. These concern separate experiments, not one combined memory/speed
claim. See [batching](VIEWER-LOD-BATCH-MODERATE-20260910.md) and
[selection retention](VIEWER-SELECTION-RETENTION-20260911.md).

## Comparison with FreeCAD

FreeCAD keeps an editable document and updates the affected objects. On the
same STEP and machine, its headless geometry edit/recompute measured 6.43 ms;
a retained placement change measured 0.042 ms. Meshing the changed part
separately took about 4.15 ms. Exporting the whole assembly to STEP still took
about 222 ms, and reading that export back took another 208 ms.

Cadgen has adopted several corresponding mechanisms: retained browser geometry,
component references, reusable pure feature factories, decorated-child
dependencies and preview publication before persistence. Its remaining gap comes from rerunning arbitrary Python
model bodies, validating private native ownership, publishing reusable canonical
objects and moving display data into a browser. Headless OCCT itself does not
impose this gap—the FreeCAD measurements were also headless.

We did not measure FreeCAD GUI frame latency or establish equal display-mesh
quality. Native meshing was tested on bounded fixtures; its complete extraction
cost was worse on curved parts, so the production JS mesher remains. See the
[FreeCAD measurements](WARM-COMPARISON-20260910.md#freecad-on-the-same-step) and
[native meshing decision](RWGLTF-MODERATE-QUALITY-20260910.md).

## Earlier validation checkpoint

The geometry/display integration passes **1,725 package Python tests and 1,014
shared JavaScript tests**. The later CLI correction passes 89 focused tests,
including seven new tests; the final viewer passes **514 client tests**. Browser
checks pass 12 lifecycle and 12 adaptive/resize assertions, plus nine direct
canvas-selection assertions after the reported bug was fixed. Details and
retained failed attempts are in the
[integration report](DEFERRED-SURF-INTEGRATION-20260911.md).

The isolated installed wheel matches 187 Python files and 29 bundled runtime
files to source. The full integration check passes 21 commands covering ordinary
decorated child builds, source-free STEP/mesh exports, corruption repair, posed
images and animation. The final CLI/viewer follow-up passes 25 expected command
outcomes, including deliberate stale-sidecar rejection, and verifies all 22
current HTTP viewer assets and the actual kernel-free server. Media paths were
unchanged by those follow-up fixes.

The new local play viewer is
[the planetary assembly on port 3264](http://127.0.0.1:3264/?file=planetary.step).
It also contains 3-part and 24-part drilled-plate examples in its file picker.
The existing viewer on port 3277 is preserved. Final follow-on validation is
recorded separately in the [integration report](FOLLOWON-INTEGRATION-20260911.md).

Automatic approval review rejected the proposed 128-build planetary procedural
study as sustained assembly stress testing; no run started. The smaller
three-part check completed successfully. It cannot establish the final nine-part
250 ms preview target, which remains explicitly unverified after the last

The later [viewer quality correction](VIEWER-QUALITY-20260911.md) restores
standard detail automatically after the first preview and prefers cached standard
meshes on reopening. Saved Moonwatch reaches all 256 standard meshes in 85.81 s
with a cold display cache, or 1.22–1.32 s warm. All 256 standard mesh objects
match the previous standard-quality snapshot. This closes the coarse-display
regression; it does not establish instant cold rendering or FreeCAD parity.
