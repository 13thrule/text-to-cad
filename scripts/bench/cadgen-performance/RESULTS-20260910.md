# Cadgen performance study — 2026-09-10 UTC

Keep the current canonical JS mesher. Native OCCT meshing is faster in its
kernel stage on this fixture, but Python extraction consumes that saving at
the default LOD. The study does not demonstrate equal visual quality or an
end-to-end viewer improvement. The warm-build changes publish a preview about
0.41 seconds before the saved result, but the 250 ms preview target is not met.

## Native OCCT experiment

[Merged results](results/native-20260910.json) and the six sibling JS, OCCT,
and decoder reports retain each component/LOD sample and its quality audit.
The runtime source digest was
`5810c50b038c5ef2ca40b034dd57db86e045eea95a8280d22793df8c8b166257`;
`runtimeUnchangedDuringStudy` is true. Both algorithms produced identical
bytes across all repetitions and the two fresh process trials.

Each component was sampled three times in each of two process trials. The
tables report the median of six sums over the nine components, rather than an
observed browser load or a single continuous assembly operation. Every sample
meshes from untriangulated inputs; OS filesystem caches are warm. Native uses
a fresh private BREP reconstruction, no parallel meshing, and the same physical
component-scale chord and 0.35-radian angular inputs as JS. The JS tessellator
version is 1 and the candidate transport codec is TESS v3.

### Geometry and reference checks

All decoded face and triangle-side references are in range for both algorithms.
The native candidate contains all 582 face ordinals and all 1,692 edge
polylines; analytic normals are defined at every sampled node and have unit
length. Its triangle-side convention follows the production renderer's
opposite-vertex mapping. This checks payload structure and local references,
not interactive selection, screen-space edge appearance, or transformed picking.

| Default-LOD audit | Current JS | Native experiment |
| --- | ---: | ---: |
| Maximum component volume error | 0.986% | 1.011% |
| Maximum per-face area error | 0.449% | 1.011% |
| Degenerate triangles | 0 | 0 |
| Unmatched quantized mesh edges | 6 | 0 |
| Inconsistent welded-edge winding | 3 | 0 |
| Triangle/normal orientation flags | 32 | 0 |

Volume and area errors compare the triangulation with exact OCCT property
queries on the same BREP. The edge-weld check rounds positions on a grid of
`max(1e-7 mm, component.scale * 1e-6)`, so it is a diagnostic heuristic, not a
topological watertightness proof. Its JS edge/winding flags occur on the carrier;
normal flags also occur on gears. At coarse LOD, the JS audit reports four
degenerate triangles and 60 triangle/normal orientation flags. Those findings
warrant targeted investigation of the existing mesher, rather than an assumption
that its quality is already a reference standard.

Equal tolerance inputs produce different error/count tradeoffs. This study
does not establish matched visual quality, a common maximum surface-deviation
bound, or acceptable appearance at both LODs. It covers planar/cylindrical
trimming, holes and seams, but leaves B-splines, singular normals, mirrored
instances, and a wider STEP corpus for a future adoption gate.

### Ownership and decision

Native triangulation changed the private shape's canonical BREP serialization
hash for **all nine components**, even when serializing without triangles or
normals. Hashes stayed unchanged during the earlier exact-property queries and
the later array extraction; the change occurs during meshing. Every input BREP
file stayed byte-for-byte unchanged. Native meshing therefore must own a fresh
reconstruction and must not mutate a materialization shared with model execution
or component identity generation. The candidate never publishes to the store.

Keep the current JS mesher as the canonical implementation. A native replacement
would require a durable extraction implementation, verified face/edge/render
semantics, a broader matched-quality corpus, and explicit cache/export versioning.
A display-only implementation would additionally require a stated contract for
how display differs from export; neither scheduling nor memory pressure may
silently select different export bytes. Native candidates in this experiment
use private filenames, never the current mesher's cache key.

The default-LOD CPU delivery times are indistinguishable at this sample size,
native process memory is higher, and browser transport/main-thread/GPU costs
remain unmeasured here. Those costs should be measured independently before
crediting any kernel reduction as a viewer improvement. The evidence supports
retaining the current implementation and investigating the measured JS quality
flags separately.
